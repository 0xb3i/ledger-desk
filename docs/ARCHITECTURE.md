# 架构说明

轻记的当前链路是“招商银行提醒邮件 → QQ 邮箱 INBOX → Mac 本地只读 IMAP 同步 → 本地 1.1.5 解析器 → SQLite → 本地看板”。Cloudflare 和飞书均不参与这条链路。SQLite 保存轻记的账目状态、编辑、审计和同步身份；原飞书历史导入记录完整保留。

## 运行方式

网页由 React 和 Vite 构建，界面基于 shadcn/ui（Radix 交互底层 + Tailwind CSS v4，组件源码在 `src/client/components/ui`），图表使用 shadcn Chart（Recharts）；Hono 处理 API，Node.js 24 的原生 SQLite 驱动提供持久化。静态网页和 API 使用同一个本机地址 `http://127.0.0.1:43927`，不开放局域网或公网访问。

`轻记.app` 是启动入口：确保用户级 LaunchAgent 已运行，等待数据库健康检查成功，再打开 `/local/open`。LaunchAgent 在用户登录后启动，进程异常退出后自动重启，不依赖浏览器保持打开。电脑休眠和关机期间不会继续同步。

Vite SSR 将服务及运行依赖打包为 `dist-local/server.mjs`，仅 Node 内置模块保持外部引用。安装产物还包含 `dist/`、`migrations/` 和 Node.js 24 二进制，不包含开发用 `node_modules`。安装器通过独立发布目录和 `current` 软链切换程序，持久数据单独存储。

## 模块边界

| 模块 | 职责 |
| --- | --- |
| `src/client` | 总览、账单、订阅、心愿单、分类与规则、同步与备份界面；`components/ui` 为 shadcn 官方组件源码，按需在源码中定制 |
| `src/shared/contracts.ts` | 前后端公共协议和备份结构 |
| `src/server` | 公共 API、认证、错误处理和数据管理 |
| `src/server/ledger` | 金额与时间校验、招行解析、幂等、核对和统计 |
| `src/server/budgets.ts` | 月度总预算的读取与带版本修改，纳入备份；不按类目拆分 |
| `src/server/wishlist.ts` | 心愿单持久化、价格校验、幂等创建、版本检查、已购与移除恢复；不生成账目 |
| `src/server/subscriptions.ts`、`src/shared/subscriptions.ts` | 订阅持久化、周期与到期推算、提醒窗口、本期已付、结束与恢复；不生成账目 |
| `src/local/server.ts` | 本机网络边界、启动入口、静态资源和进程生命周期 |
| `src/local/database.ts` | 用本地 SQLite 实现项目实际使用的数据库查询与事务契约 |
| `src/local/migrations.ts` | 追加迁移、已应用迁移哈希校验 |
| `src/local/mail.ts`、`src/local/imap.ts`、`src/local/mime.ts`、`src/local/keychain.ts` | QQ 邮箱只读 IMAP（`EXAMINE INBOX`）增量同步、MIME 解码、macOS 钥匙串凭据管理与历史衔接防重 |
| `src/server/ledger/cmb-email-parser.ts` | 招行提醒邮件 1.1.5 解析器（保持与原快捷指令一致的 SHA-256 指纹与字段标准化） |
| `src/local/feishu.ts` | 历史飞书同步模块（定时轮询已停用，保留表结构与历史导入记录） |
| `scripts/build-local.mjs`、`scripts/install-local.mjs` | 独立运行包、安装、启动器和服务配置 |

本地数据库适配保留现有领域代码与参数绑定，不模拟云端副本或计费语义。批量操作在同一 SQLite 连接的事务中完成；事务内部不跨异步等待，避免请求交叉执行。数据库启用外键、WAL 和繁忙等待。

## 账本规则

金额以整数分存储，输入严格转换后入库；支出、收入、退款和转账的金额均为正，业务含义由类型表达。交易时间包含时区，月份归属和展示采用 `Asia/Shanghai`。

退款单独统计，转账保留类型与方向，转账按本账户资金方向计入收入或支出，未知方向留待确认。撤销和待核对记录不计入已确认汇总。修改、撤销与恢复要求提交当前版本，版本冲突返回 409；审计和业务变化一起持久化。

幂等键用于同一请求重试，交易指纹用于提示疑似重复。不同记录具有相同指纹时保留待核对账目，不将指纹当作银行流水号。手工录入、邮件导入和待核对补录共用账本保存函数。

## 邮箱同步

本机服务以只读方式检查 QQ 邮箱收件箱。首次同步按起始日期搜索，随后按 UID 增量读取，邮箱 UIDVALIDITY 变化时重新从起始日期检查。按日期范围补扫沿用去重规则，保留增量游标。服务先在本地筛选邮件头，再读取符合条件的正文。

启动和每 5 分钟触发同步，设置页可手动触发。账号、目录、目标账户、UIDVALIDITY 和 UID 共同确定同步身份。单封正文过大或无法解码时进入待核对，连接或协议失败则保留增量游标供重试。

## 安全与持久化

服务校验精确 Host 与本机 Origin，`/local/open` 还限制浏览器请求来源。启动入口直接建立 HttpOnly、SameSite=Strict 会话，再重定向主页；网页写入继续校验同源。自动登录只针对当前操作系统用户可访问的本机服务，不能把它暴露成公网免密入口。

`data/`、发布目录及日志目录限制当前用户访问。数据库、会话密钥和邮箱配置按私密文件保管。日志只记录可诊断的错误类别与请求 ID，不记录银行邮件、账目正文、访问令牌或密钥。

数据迁移只追加新文件，启动时检查已应用迁移的内容哈希。重装和程序更新不覆盖 `data/`；程序回退不会撤销数据库结构变更。

## 备份与历史云端

应用备份包含账户、分类、账目、账目幂等回执、分类规则、二级标签及手动指定、月度预算、心愿单和订阅，不包含会话密钥、设备令牌、心愿创建请求哈希及完整审计。完整恢复需要在服务停止后保管整个本地数据目录。恢复策略见 [本地运行与维护](OPERATIONS.md)。

历史 Cloudflare 应用及 D1 保持原部署，供旧账目保管；本地应用不把它作为中转或备用数据源，不自动与旧云端合并数据。
