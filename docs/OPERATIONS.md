# 本地运行与维护

## 当前运行方向

轻记当前以 Mac 本地应用交付，直接通过只读 IMAP（`imap.qq.com:993`、`EXAMINE INBOX`）自动拉取 QQ 邮箱中的招商银行提醒邮件。原飞书定时同步已停用，不再依赖飞书 Webhook 或手机快捷指令；历史通过飞书导入的账目完整保留在本地 SQLite 中。

## QQ 邮箱同步配置

在「同步与备份」页面填写 QQ 邮箱地址、QQ 邮箱网页版生成的 16 位 IMAP 授权码以及起始同步日期，验证连接后即开启自动同步：

- 非凭据配置保存在 `~/Library/Application Support/Qingji/data/mail.json`（权限 `600`），仅包含邮箱地址、`imap.qq.com:993`、`INBOX`、目标账户 `cmb-default` 和起始同步日期。
- 16 位授权码通过 `/usr/bin/security -i` 写入 macOS 系统钥匙串（服务名 `local.qingji.dashboard.qqmail`），不写入明文配置、日志或应用备份。
- 同步仅使用 `EXAMINE INBOX` 和 `BODY.PEEK`，不删除邮件，不改变邮件的未读/已读状态。
- 首次连接及与原飞书重叠的日期区间，按 `1.1.5` SHA-256 交易指纹自动跳过已存在的历史账单，不会重复入账；支持在设置页按日期范围手动补扫（超过 30 天的历史邮件需先在 QQ 邮箱网页版将“收取选项”改为“全部”）。

历史 Cloudflare 应用与本地账本相互独立。当前版本的邮箱同步和日常使用不依赖该云端部署，云端数据也不会自动合并到本地账本。

## 安装与目录

在 Node.js 24 开发环境中执行：

```sh
npm ci
npm test
npm run test:shortcut
npm run install:local
```

安装依次执行类型检查、网页构建和服务打包，验证 Node.js 24，复制独立运行包，配置 LaunchAgent 并启动服务，最后检查 `/api/health`。安装器在当前用户下运行，不能使用 `sudo`。

| 位置 | 内容 |
| --- | --- |
| `~/Applications/轻记.app` | 双击启动入口 |
| `~/Library/LaunchAgents/local.qingji.dashboard.plist` | 用户登录时启动和异常退出后重启 |
| `~/Library/Application Support/Qingji/releases/` | 各次构建的独立程序，包含 Node.js |
| `~/Library/Application Support/Qingji/current` | 当前程序目录的软链 |
| `~/Library/Application Support/Qingji/data/ledger.sqlite` | 本地账本、审计和同步状态 |
| `~/Library/Application Support/Qingji/data/local-access-key` | 自动生成的本机会话密钥，不显示或分享 |
| `~/Library/Application Support/Qingji/data/mail.json` | 邮箱地址、同步起点和目标账户 |
| `~/Library/Application Support/Qingji/logs/` | 服务启动及脱敏错误日志 |

程序安装后不再依赖源码目录、Wrangler 开发服务或项目的 `node_modules`。

只做安装预检：

```sh
npm run build:local
node scripts/install-local.mjs --dry-run
```

预检可能为 Node.js 24 准备本机 npm 缓存，但不会安装应用、注册服务或启动数据库。正式安装已构建产物并打开应用：

```sh
node scripts/install-local.mjs --open
```

## 本地访问

日常双击“轻记”，或从浏览器地址栏直接打开 [本地入口](http://127.0.0.1:43927/local/open)。启动器等待健康后再打开网页。入口建立本机会话，密钥不放入地址栏、命令参数或日志。

使用精确地址 `127.0.0.1:43927`，不要改用 `localhost`、局域网 IP 或配置反向代理。其他设备不能直接访问这台电脑的看板。

后台服务与浏览器分别运行。关闭网页不会停止同步；退出 macOS 用户、关机或休眠期间不运行。恢复登录、运行和联网后会继续读取邮箱，已在本地保存的记录可离线使用。

## 邮箱配置

在「设置 → 邮箱同步」连接 QQ 邮箱，填写邮箱地址、IMAP 授权码和同步起始日期。服务验证连接后立即同步。授权码保存在 macOS 钥匙串，更换授权码时可在同一处更新。

## 更新与服务管理

更新后运行 `npm run install:local`。安装器创建独立发布目录，保留数据与原会话密钥，切换当前程序并重启；健康检查通过后只保留当前和前一个程序版本。失败时查看日志、修正后重跑，不能通过删除数据库绕过迁移错误。

查看服务状态：

```sh
launchctl print gui/$(id -u)/local.qingji.dashboard
```

完整备份或维护前停止服务：

```sh
launchctl bootout gui/$(id -u)/local.qingji.dashboard
```

恢复运行可再次双击“轻记”。如需卸载程序，先停止服务，再移除对应 LaunchAgent 和“轻记.app”；数据目录独立保留，由用户确认备份后另行处理。

明确的“财付通-微信支付-微信转账”或“微信转账”摘要在入库时归为转账，兼容旧手机解析器把到账标为退款的情况；含退款、失败、手续费等附加描述仍按原交易类型处理。原始来源类型和请求回执保留。

## 招行账户收支

转账保留独立类型，按本账户方向计入收支：转入计入收入，转出计入支出；转账信息不再重复加入汇总。原飞书和快捷指令的资金方向会带入旧记录，方向未知的历史转账不猜测，可在账单编辑中选择转入或转出。手工新增转账也必须选择方向。

AA 示例：招行支付餐费 100 元，朋友的 50 元进入微信余额后提现到招行，该账户记录支出 100 元、转入收入 50 元，结余减少 50 元。当前只采集招行流水，微信余额收到款项时尚未成为本账户流入；提现流水计一次收入。

## 退款抵扣

总支出、分类、分日图、固定支出和日均使用匹配退款后的实际支出。相同账户与币种、已确认且未撤销的退款，只在原消费之后 90 天内寻找明确的商户摘要与金额匹配；同额优先，部分退款需只有一个可对应消费。多个候选或累计退款超过消费金额时不自动抵扣。退款不重复使用，不能仅靠平台名匹配。

原消费与退款记录、金额、类型、版本和请求回执不改写。全额退款显示标记，部分退款显示实际剩余金额；详情可查看原金额及抵扣额。跨月退款抵扣原消费月份，收支结余仍按实际收付款发生月份计算，不二次减退款。备份保存原始账目，恢复后按同一规则重新计算。

## 类目管理

从“账单 → 分类设置 → 类目”新增或编辑类目，设置名称、收支范围、图标与颜色。图标来自随应用打包的 Lucide 库，提供 30 个常用图标与搜索，颜色沿用轻记的 7 种浅色。类目改名及外观修改使用稳定类目 ID，不改账单金额、原类型或手工分类。已有账单、规则引用的类目不能改为不兼容的收支范围。删除前可查看关联账单、分类规则及将随类目删除的二级标签和标签规则。已有关联账单或规则时，先选择接收它们的兼容类目。

## 自动分类

从账单页的“分类设置 → 自动规则”管理关键词、收支范围和目标分类，可修改或停用内置规则，也可新增自己的规则。新账单入库时自动匹配；保存、启用、停用或删除规则时，历史账单同步重新匹配，返回实际更新笔数。未分类与规则分类参与重算，手工分类、手工清空、已撤销账单和方向未知的转账受保护。“重新匹配历史账单”可查看并应用当前规则的变化。

分类规则在本机执行，不发送账单给外部模型。手工分类和手工清空会受保护；修改备注不会取消原分类来源。退款可归到原消费类别，有方向的转账按收入或支出规则分类。规则分类随规则调整更新；停用或删除后重新匹配其他规则，无明确匹配或规则冲突时回到未分类。相同分类依据不重复更新。规则保存和历史更新在同一事务完成，不改变飞书记录或原始请求指纹。

## 备份与恢复

日常从设置导出应用账本。备份格式版本 7 包含账户、类目名称、图标与颜色、转账方向、分类规则、人工／自动分类来源、固定支出标记、当前及已撤销账目、结构化来源、请求回执、二级标签及手动指定、月度预算和心愿单，不包含任何密钥、会话或完整审计。保存到独立存储，不能只留在同一台电脑。

新程序同时接受格式版本 1–7；版本 1 的记录默认为非固定支出，旧版已有分类、人工创建或编辑过的空分类按人工选择保护。应用恢复采用追加方式：相同 ID 和相同内容跳过，有差异返回冲突，规则和账目整批写入保持原子性，不覆盖已编辑账目。内置默认规则保留在代码中，用户覆盖保存在数据库，因此新安装恢复已修改规则的备份不会与默认种子冲突。自定义类目和样式同样进入备份；新空库可恢复备份中修改过的默认类目，已使用或修改的现有类目遇到差异时不覆盖，旧备份也不会覆盖当前样式。新空库的默认二级标签可按备份完整恢复，已定制的目标库遇到冲突时保留现有数据。恢复请求上限为 8 MB。

需要完整副本时，先停止 LaunchAgent，确认服务已停止，再复制整个 `Qingji/data` 目录到私密备份位置；不要在服务运行时只复制 `ledger.sqlite`，遗漏 WAL 中尚未合并的数据。完整目录包含认证和配置文件，应加密或限制访问。

恢复完整目录前保留当前副本，保持服务停止；恢复后检查数据库迁移、账户、记录数、月度汇总和同步状态，再恢复日常运行。程序更新与数据库恢复是两个操作，安装器不会自动撤销迁移。

## 快捷指令维护

飞书模板使用解析器 `1.1.5`。运行签名命令可生成 `public/shortcuts/cmb-feishu-1.3.1.shortcut`，导入后再填写自己的 Webhook 配置。已配置的个人副本含凭据。生成器只生成或签名模板，不会自动运行快捷指令。

```sh
python3 scripts/validate-shortcut-native.py --kind feishu
python3 scripts/build-feishu-shortcut.py --sign
```

新版在保留原邮件指纹构造的基础上识别完整微信转账摘要，流入输出 `transfer_in` 和“转入”，流出输出 `transfer_out` 和“转出”。飞书工作流直接写入 `transaction_type_label`，生产表已补充“转入”选项，保留既有选项。Mac 与手机已有的 `1.3.0` 个人副本不会随应用安装自动替换；导入 `1.3.1` 时沿用旧副本的 Webhook 配置，并将手机自动化切换到新指令。

银行邮件只有月日的时间会使用设备当前年份；跨年历史邮件需要核对年份，不能批量重放。每次运行产生新请求 UUID，网络错误不会建立跨运行离线队列。先核对飞书和轻记记录，再决定是否重试同一封邮件。

旧手机直连模板和云端部署仅保留历史兼容背景，不作为本地接入方式。电脑上的 `127.0.0.1` 地址不能填进 iPhone 直连模板来访问 Mac。

## 故障处理

| 现象 | 检查方式 |
| --- | --- |
| 双击后无法打开 | 查看 LaunchAgent 状态、端口占用及私有服务日志；确认程序发布目录仍完整 |
| 提示本机入口无效 | 从地址栏打开 `http://127.0.0.1:43927/local/open`，不要经其他网站或代理访问 |
| 邮件已收到，账单未出现 | 在设置查看最近同步和待核对邮件，必要时按邮件日期补扫 |
| 邮箱授权或网络错误 | 检查 QQ 邮箱的 IMAP 设置和本机网络，授权码失效时在设置中更新 |
| 某条记录需要核对 | 检查其金额、时间、类型或来源变更；本地不会悄悄覆盖已有账目 |
| 数据库迁移校验失败 | 使用匹配的程序版本或追加修正迁移，不修改已应用迁移或删除迁移记录 |
| 重装后看不到原账本 | 核对 QINGJI_DATA_DIR 是否仍为原 `Qingji/data`，不要创建第二套数据目录 |

日志只保留错误类别、请求 ID 和必要运行信息，不输出银行邮件、账目正文、配置对象或凭据。健康检查证明服务和数据库可访问，不能代替每笔真实交易核对。
